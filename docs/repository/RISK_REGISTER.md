| `settings.html`'s admin-only "مسح البيانات" (reset/delete) buttons are gated only client-side (`u.role==='admin'` check before rendering, and now also inside each `window.reset*` function) — the underlying collections' Firebase rules (`animals`, `health`, `vaccinations`, `breeding`, `activity_log`, `notifications`, `login_notifications`) require only `auth != null`, not `role === 'admin'`. A non-admin session could still call these destructive functions directly (e.g. via browser devtools), or `DELETE` those paths directly over the REST API, bypassing the app's UI/JS entirely | Core/Security | High — irreversible mass-delete with no automated backup/restore mechanism (see `docs/architecture/SCALABILITY-REVIEW.md`) | Confirmed by direct rules inspection, 2026-08-23. Client-side compensating check added in `settings.html`'s `window.reset*` functions as a stopgap; closing this properly means adding `role==='admin'` write restrictions to those collections' `database.rules.json` entries, deliberately left untouched this pass since another active session was concurrently editing that exact file for the accounting-engine rollout |
| **No HTML-escaping helper exists anywhere in the codebase** (`grep`-confirmed: zero `escapeHtml`/`sanitize`-style function in `shared.js`/`firebase.js`). Free-text fields the app lets any writing role enter (animal/weight/vaccination/medication notes, confirmed by direct read of `animal-detail.html`; almost certainly many more given `.innerHTML=` is, per `scripts/safety-scan.js`'s own note, "a pervasive, already-established pattern across this codebase") are concatenated straight into `.innerHTML=` template strings with no escaping | Core/Security | **Critical, confirmed exploitable, not fixed** — proved live with a harmless `<img src=x onerror=...>` payload rendered through the exact template `animal-detail.html` uses for weight notes; the handler executed. Severity is compounded, not just theoretical stored-XSS: every admin action in this app (including the destructive `settings.html` reset functions above) is a globally-callable `window.*` function gated only by `getUser().role` read at call time — a payload planted by ANY writing role, later viewed by an admin, executes with that admin's real session and full privileges. Full remediation is a real, wide undertaking (adding an `escapeHtml()` helper is trivial and safe to do any time; auditing and updating every `.innerHTML=` interpolation site across this many files to actually use it is not something to fold into a routine pass — same "needs its own evidentiary rigor" bar as the certified SSOTs, not attempted here to avoid a partial fix creating false confidence while leaving most of the real attack surface untouched) | Confirmed live, 2026-08-23, via an isolated scratch-element test — no payload was ever written to Firebase |
