## Highest-severity findings

1. **`assistant.html` — prompt injection + reflected/echo XSS in the AI chat.** The LLM's own JSON response (`answer`, `summary`, and every extracted field like `breed`/`notes`/`diagnosis`) is rendered via raw `.innerHTML=` with zero escaping (lines 467, 582-605, 610-639, 732-763, 806-812). Since the system prompt (`buildFarmContext()`) itself embeds unescaped medicine/feed names, health diagnoses, and task titles, this is a two-way exposure: tainted farm data can ride into the model's context, and the model's output (or a jailbroken response) renders unescaped back into the page — including the "extracted data" confirmation card that displays *before* the user confirms a save.
2. **`pages/pedigree.js` — worst density of any file audited.** Six sites, all rendering raw `animals.breed`/`animals.tag` with zero restriction, some in `aria-label="..."` attributes (breakout risk). Reachable just by opening `pedigree.html` for any animal with a tainted parent/sibling/offspring/search-result record — no special user action needed.
3. **`pages/reports.js` — 6 clusters**, the same `medicine.name`/`health.medication`/`finance.description`/`vaccination.name` free-text fields already fixed elsewhere in the app, unfixed here.
4. **`dashboard.html` — 2 clusters** covering low-stock alerts, the tasks widget, the operational timeline, the activity-log timeline, and the priority list — all on the page every user sees first after login.
5. **`barns.html`, `births.html`, `goats.html`/`sheep.html` — attribute-breakout risk**, not just text-content injection: several sites interpolate `breed`/`tag` directly into `value="..."` / `option value="..."` without quoting, so a value containing `"` plus an event handler executes on next render.

## Confirmed-safe pattern worth reusing

Every `finance-*.html` page and the already-remediated choke points (`toast()`, notification renderers, `renderNavbarV2`) route free text through `escapeHtml()` before interpolation. The fix for every VULNERABLE finding above is mechanical: wrap the named field in `escapeHtml()` at the identified line — no new helper needed, no architecture change.
